# Plan 3 of 3: notebooks, playgrounds, and Jupyter inside the site

## Context

- **Plan 1** (`plans/2026-10-16_course_curriculum.md`) wrote the course. It is in `synth_course/`.
- **Plan 2** (`plans/2026-10-16_course_website.md`) built the local site, `synth_course/site/`:
  - Next.js 16 plus SQLite, run in Docker via `make dev`
  - one playground so far, a port of the old `web_sim`

Every module's **Explore (notebook)** and **Play (playground)** section is still only a
specification. This plan builds them.

Decided with the user:

- **Python runs inside the site's container.** There is no local Python and no second
  container.
  - The site image gains Python and the scientific libraries, plus JupyterLab.
  - `make dev` starts both servers.
  - Each module page embeds its notebook.
- **Sound in notebooks** plays in the browser via `IPython.display.Audio`; `sounddevice` is
  dropped.
- **Hardware data** is handled as files:
  - The container can't reach the audio interface or the board's serial port.
  - Line-out recordings and Serial logs are captured on the Mac and dropped into
    `synth_course/notebooks/recordings/`.

## Part A: one image, two servers

**Image** (`synth_course/site/Dockerfile`):
- Switch the base to `node:22-bookworm`, which has Python 3.11.
- Add `python3-venv` and a venv at `/opt/venv` holding pinned `numpy`, `scipy`,
  `matplotlib`, `jupyterlab` and `ipykernel`, installed from a committed
  `synth_course/notebooks/requirements.txt`.
- The venv lives in the image, not a volume, so it's rebuilt only when `requirements.txt`
  changes (`make image`).

**Start script** (`synth_course/site/dev.sh`, the container's command for `make dev`):
- Starts `jupyter lab` in the background on container port 8888, with:
  - root dir `/notebooks`
  - no token or password (it's published on localhost only)
  - `ServerApp.tornado_settings` CSP `frame-ancestors 'self' http://localhost:${PORT}`, so the
    site may embed it
  - `ServerApp.allow_origin` set to the site's origin
- Then runs `next dev` in the foreground.
- Stopping `make dev` (Ctrl-C) stops both, via a `trap`.

**Makefile:**
- Publish `JUPYTER_PORT ?= 8888` as well (8888 is free on this machine).
- Mount `synth_course/notebooks` read-write at `/notebooks`.
- New targets:

  | Target | Does |
  |---|---|
  | `make nb-check` | run every *solution* notebook headless (`jupyter nbconvert --execute`); fail on any error |
  | `make e2e` | the headless-browser smoke test (Part D) |

**Site:**
- The module page's sidebar notebook line becomes an **"Open notebook"** button. It
  expands an iframe panel under the article, loaded on click rather than with the page, with
  `src = ${NEXT_PUBLIC_JUPYTER_URL}/lab/tree/<module-id>.ipynb` and a "pop out" link.
  `NEXT_PUBLIC_JUPYTER_URL` defaults to `http://localhost:8888`, set by the Makefile from
  `JUPYTER_PORT`.

**Course text:**
- Module 00's Explore section changes: no local Python setup. Run `make dev` and open
  `00-toolchain-and-board.ipynb` (the setup check) to check the libraries load and audio plays.
- Replace `sounddevice` with `IPython.display.Audio` in `curriculum.md` (software list)
  and the modules that mention it.
- Add a short "Recording from the hardware" paragraph to `curriculum.md` (the kit section)
  describing the recordings folder workflow.

## Part B: notebooks

**Layout:**

```
synth_course/notebooks/
  requirements.txt
  synthlib.py            shared helpers (below)
  00-…ipynb … 16-beyond.ipynb   the exercises, named <module id>.ipynb
  solutions/NN-….ipynb   worked solutions, same structure
  reference/             module 01's reference WAVs (generated by its solution)
  recordings/            your hardware captures (gitignored except a README)
```

**`synthlib.py`** holds only what three or more notebooks need:
- `play(x, fs)` (IPython Audio)
- `write_wav` / `read_wav` (scipy.io.wavfile, int16)
- `spectrum_db(x, fs)` and `plot_spectrum(...)`, with harmonic markers
- `db()` / `amp()`
- `midi_to_hz` / `hz_to_midi` / `note_name`
- `q15_mul` / `sat16` (numpy int32)
- `load_serial_log(path)` (numbers from a Serial capture)

Each notebook names what it imports.

**Scaffold format** (what you work in):
- Markdown cells restate each numbered step from the module's Explore section.
- Each step has a code cell with the setup done and a clearly marked `# TODO`.
- Then a **check cell** asserts something about your result (e.g. "the 30 kHz sine's peak is
  at 14.1 kHz ± 50 Hz"). Checks are written so they *fail* until the TODO is done, and say
  why in the message.
- The final markdown cell holds the module's "Aha", to compare against your own conclusion.

**Solutions:**
- Same cells with the TODOs filled in.
- Linked from the module's Compare (spoiler) section, so they stay behind the same spoiler
  rule.
- Notebooks that need *your* recordings (03, 06, 07, 12, 15: the "if recording" steps) fall
  back to a synthetic signal when `recordings/` has no file. Solutions therefore always
  execute.

**Content source:** each module's existing Explore section is the spec, already written in
plan 1. Notebook 16 is a skeleton only: headings for prototype, render and measure.

## Part C: playgrounds

There are 17 playgrounds, built from each module's existing Play section: module 05 has two
(knob lab and encoder lab), and module 16 has none.

**Shared code**, built first because most labs are combinations of it:

- `playgrounds/shared/engine-worklet.js` (in `public/worklets/`): one AudioWorklet engine
  driven by messages. It provides:
  - N wavetable voices, with tables built on the main thread and posted in
  - pitch per voice
  - mix normalization mode (none, 1/N, sum-to-one) with a clip flag
  - ADSR amp envelope with gate and retrigger, ramped per sample or stepped per block
  - one-pole low-pass with its own envelope
  - LFO (vibrato and tremolo, delay and onset)
  - waveshaper (hard, soft, fold, crush; pre or post mix)
  - sample-and-hold and requantize, for the aliasing and bits lab

  These are integer/Q15 ports of the same algorithms the course teaches, so the labs
  *sound* like the hardware.
- `playgrounds/shared/ui/`: `AudioStart` (the user-gesture button), `Slider`, `Scope`
  (triggered time-domain view), `Spectrum` (log-magnitude from an `AnalyserNode`),
  `CurvePlot` (canvas plot for transfer curves, ADSR shapes and responses), and `Oled`
  (72×40 canvas).
- `playgrounds/shared/wavetables.ts`: harmonic weights → band-limited table (per octave, or
  off, or exact), the module 07 algorithm.

**Playgrounds** (id → module). Each is one folder with a component plus a default state, and
is registered in `meta.ts` and `components.ts`:

| id | module | built on |
|---|---|---|
| `oled-window` | 00 | Oled |
| `harmonic-ear` | 01 | engine (one voice, custom table) + Spectrum |
| `aliasing-bits` | 02 | engine S&H/requantize |
| `i2s-scope` | 03 | CurvePlot (timing diagram), no audio |
| `scheduler` | 04 | canvas timeline simulation, no audio |
| `knob-lab` | 05 | engine + `smoothValue`/`mapPitchHz` with a simulated noisy ADC |
| `encoder-lab` | 05 | canvas waveforms + two decoders, no audio |
| `dds-wheel` | 06 | engine (accumulator bits / table size params) |
| `harmonic-lab` | 07 | wavetables + engine + Spectrum |
| `voice-mixer` | 08 | engine voices + normalization |
| `key-explorer` | 09 | scale math (TS port of the module's spec) + engine |
| `oled-layout` | 10 | Oled |
| `adsr-lab` | 11 | engine ADSR + CurvePlot |
| `brightness-lab` | 12 | engine filter + Spectrum + CurvePlot |
| `vibrato-lab` | 13 | engine LFO + pitch/amp traces |
| `waveshaper-lab` | 14 | engine shaper + CurvePlot + Spectrum |
| `instrument-lab` | 15 | wavetables (model functions) + engine |

- **web-sim stays** as the "Simulator" nav entry.
- **Presets:** every playground's state is plain JSON, so presets work for all of them with
  no extra code. Labs that the module text gives presets for (e.g. vibrato "reed / flute /
  bowed") ship them as built-in presets alongside the user's saved ones.

## Part D: checks

- `make check` additionally verifies:
  - every module except 16 has `notebooks/<id>.ipynb` and `solutions/<id>.ipynb`
  - each notebook is valid JSON
  - every module except 16 has at least one playground registered in `meta.ts`
- `make nb-check`: all solutions execute without error, and their check cells pass.
- `make test`: add vitest unit tests for the pieces with real logic, comparing against
  hand-computed values:
  - `wavetables.ts` (harmonic count per level, peak normalization)
  - the scale math
  - the encoder decoders
- `make e2e` (Playwright image, `--network container:` the dev container), for every
  playground:
  - the page loads with no console errors
  - "Start audio" succeeds where there is audio
  - one control changes state
  - a preset saves and reloads
  - each module page's notebook panel opens and the iframe reaches JupyterLab
- **Ears:** listening is the one thing automation can't do, so the final report will list
  each lab with what you should hear, for a one-pass manual listen.
