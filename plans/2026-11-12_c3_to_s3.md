# Move the synth from the ESP32-C3 (ABRobot 0.42" OLED) to an ESP32-S3 SuperMini

## Context

The synth targets the ABRobot ESP32-C3 board: single core, no FPU, a built-in 0.42" SSD1306
on fixed GPIO5/6, and GPIO20/21 reclaimed from UART0 via "USB CDC On Boot". It is moving to an
ESP32-S3 SuperMini, a small board with **no built-in OLED** and a different usable pin
set. The C3 build is **replaced**, not kept alongside it. Only one pin map is maintained. The
course (`synth_course/`) is out of scope and will get its own plan.

The DSP code doesn't change. The S3 runs the same Arduino-ESP32 core (3.3.11 installed), and
`ESP_I2S`, `analogRead`, `attachInterrupt` and `Wire` all route through the GPIO matrix. The
work is pins, compiling out the display, the LED, the build target and stale C3 wording.

## S3 pin constraints

- **Not usable:** GPIO0, 3, 45, 46 (strapping), 19/20 (native USB D-/D+), 26–32 (flash),
  33–37 (octal PSRAM on N8R8/N16R8 modules).
- **Pots must use ADC1 (GPIO1–10).** ADC2 (GPIO11–20) is unreliable while the radio is on.
- **Not every pin reaches a header.** The SuperMini exposes roughly GPIO1–13, 43/44 and its
  WS2812 RGB LED on 48. The map below uses only GPIO1–13.

## New pin map (`synth/pins.h`)

| Function | C3 now | S3 | Note |
|---|---|---|---|
| `PIN_POT_VOL1` | 0 | **1** | ADC1_CH0 |
| `PIN_POT_PITCH1` | 3 | **2** | ADC1_CH1 |
| `PIN_ENCODER_A` | 1 | **4** | pull-up |
| `PIN_ENCODER_B` | 2 | **5** | pull-up |
| `PIN_ENCODER_SW` | 20 | **6** | pull-up (GPIO20 is USB on the S3) |
| `PIN_AUDIO_SWITCH` (gate) | 21 | **7** | pull-up |
| `PIN_I2S_BCK` | 4 | **8** | as requested |
| `PIN_I2S_LRCK` | 7 | **9** | as requested |
| `PIN_I2S_DOUT` | 10 | **10** | unchanged |
| `PIN_OLED_SDA` | 5 (built in) | **11** | no OLED on the S3, so the display is compiled out (step 2); reserved in case one is added later |
| `PIN_OLED_SCL` | 6 (built in) | **12** | same |
| `PIN_STATUS_LED` | 8, active-low | `RGB_BUILTIN` | see step 3 |
| spare | — | 13 | |

**Verify against the actual board's silkscreen before wiring.** SuperMini clones differ.

## Steps

1. **`synth/pins.h`.** Replace the header comment (ABRobot board description → S3 pin
   constraints above) and the pin defines from the table. Remove the C3-specific notes on
   `PIN_AUDIO_SWITCH` / `PIN_ENCODER_SW` ("UART0 TX", "freed by moving BCK", "amp side of the
   QFN32 package"), and reword the `VOLUME_Q15_SHIFT` comment (`pins.h:119`, "the ESP32-C3
   core has no hardware FPU") the same way as step 7.

2. **No OLED: compile the display out (`display.h`).** Uncomment the existing
   `#define DISABLE_DISPLAY`. `display.cpp` is already wrapped in `#ifndef DISABLE_DISPLAY`,
   and `display.h` already provides no-op inline `displayBegin()` / `displayUpdate()`, so
   `synth.ino` needs no change and Adafruit_GFX/SSD1306/Wire drop out of the build. Leave the
   `OLED_*` geometry constants and the display code as they are, so re-enabling the display
   later is a one-line change. Only `PIN_OLED_SDA/SCL` move, to 11/12, so they don't collide
   with the encoder on GPIO5.

3. **Status LED (`synth.ino`).** The SuperMini's onboard LED is a WS2812 on GPIO48. The core
   has no SuperMini variant; the generic "ESP32S3 Dev Module" variant (`variants/esp32s3`)
   defines `PIN_RGB_LED 48` and `RGB_BUILTIN` (verified in core 3.3.11), and the core's
   `digitalWrite(RGB_BUILTIN, …)` drives it as an RGB LED. The current active-low logic
   (`blinkOn ? LOW : HIGH`) flips to `blinkOn ? HIGH : LOW`.

4. **Audio task (`audio_task.cpp`, `audio_task.h`).** Keep `xTaskCreatePinnedToCore(..., 0)`.
   On the S3, Arduino `loop()` runs on Core 1, so audio now has Core 0 to itself. Update only
   the comments that describe Core 0 as "the C3's only core" and say `loop()` shares it. Keep
   the `vTaskDelay(1)` on short writes, since it still protects Core 0's idle task and watchdog.

5. **`setup()` comment (`synth.ino`).** "USB CDC On Boot" is still needed for the console over
   the native USB port, but it no longer frees any pins. Fix the comment.

6. **`player/player.ino`.** Its duplicated pin defines move to BCK 8 / LRCK 9 / DOUT 10 /
   VOL 1, and its "same board quirk" comment (`player.ino:48`, the only board-specific
   comment there) needs the same fix.

7. **Stale C3 wording in DSP comments.** In `oscillator.h:11,92`, `distortion.cpp:16` and
   `voices.h:199`, the cycle budget changes from 160 MHz → 240 MHz (3628 → 5442
   cycles/frame), and "FPU-less C3" becomes "integer-only by design". The S3 has a
   single-precision FPU, but rewriting the integer DSP isn't part of this plan.
   `WAVETABLE_RAM_BUDGET_BYTES` stays as-is. The S3 has more SRAM, so raising the budget is
   possible follow-up work.

8. **Docs.**
   - `README.md:19`: board becomes "ESP32S3 Dev Module", FQBN `esp32:esp32:esp32s3`, and the
     options are `CDCOnBoot=cdc` (USB CDC On Boot: Enabled) and PSRAM per module.
   - `CLAUDE.md`: rewrite the Tech stack platform bullet (S3, dual core, audio alone on Core 0,
     new free-pin set) and the Display bullet (no OLED on the S3, compiled out via
     `DISABLE_DISPLAY`). The liveness LED becomes the only visual status indicator.
   - `synth.ino` header comment: check it for board references.

## Verification

1. Run `synth/test/run.sh`. The host tests must still pass; only constants and comments change.
2. Run `arduino-cli compile --fqbn esp32:esp32:esp32s3:CDCOnBoot=cdc synth` and the same for
   `player`. Both must build cleanly with no `RGB_BUILTIN` error.
3. Ask the user before flashing (CLAUDE.md rule). On the board, check that the console prints
   free heap and the patch name, the LED blinks at ~1 Hz, both
   pots respond, the encoder steps one patch per detent and its push toggles distortion, the
   gate switch triggers attack/release, and sound comes out of the amp and the DAC line out.

## Out of scope

`synth_course/` (separate plan), using the S3 FPU in the DSP, raising the wavetable RAM
budget, and adding an external OLED.
