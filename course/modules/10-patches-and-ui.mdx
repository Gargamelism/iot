## Goal

Turn the synth into an instrument with presets: a compile-time table of patches, validated by
the compiler, selected by the encoder and shown on the OLED.

## You'll be able to

- Describe an instrument as data (`constexpr` tables) and derive everything else from it.
- Use `static_assert` and `constexpr` functions to make invalid data a build error.
- Switch the active patch safely while the audio task is running.
- Lay out a tiny status display and refresh it without disturbing audio.

## Concepts

- **Data-driven design.** One table row per patch: voices (offset, spectrum, level), pitch
  mode, scale, and later envelope, tone, vibrato and distortion. Code iterates the table and
  never names a specific patch.
- **Compile-time validation.** `constexpr` loops over the table inside `static_assert`.
  Bounds, enums in range, counts.
- **Resource derivation.** The set of spectra to build at boot is the *union* over all patches,
  and each spectrum's highest reachable pitch decides its top table.
- **Patch switching across threads.** The index changes in `loop()`. The audio task applies
  it at a block boundary, rebuilds its per-voice state, and never sees a new voice count with
  old frequencies.
- **OLED refresh.** I2C is slow (a full-frame transfer takes milliseconds). Rate-limit it, and
  never let it block on the shared lock.
- **Tiny layouts.** A 72×40 window, a 6×8 px font: 12 characters × 5 rows at most.

## Build

Start from module 09.

**Add:**

- **A patch table.** Each row has a voice list, a pitch mode (diatonic or detuned unison), a
  scale and a label. *Example* (illustrative):

  ```cpp
  struct Patch { const Voice* voices; uint8_t count; PitchMode mode; Scale scale; const char* label; };
  constexpr Patch kPatches[] = {
    {kTriad,  3, DIATONIC, MINOR,     "HARM"},
    {kUnison, 3, UNISON,   CHROMATIC, "UNI3"},
  };
  ```
- **Compile-time checks.** *Example* failure message: `static_assert failed: "a patch's voice
  count is out of [1, MAX_VOICES]"`.
- **Encoder → patch** with wrap, using your module 05 step counter. *Example:*
  `patch 4/12 GTR (1 voice, DIA, harm. minor)`.
- **An OLED status screen.** *Example* layout:

  ```
  SYNTH
  C#3 ########
  GTR  1v DIA
  ```
- **Boot-time table building** for every spectrum any patch uses. *Example:* `tables: 7
  spectra, 38 tables, 77824 B (budget 131072)`.

**Constraints:**

- The audio task picks up a patch change at a block boundary, and its voice count, levels
  and frequencies must all belong to the same patch.
- The display update never blocks audio and never waits long for the shared lock. Skip a
  frame instead.
- Adding a patch means adding a table row only. No other code changes.

**Deliverable:** a patch table, the validation, encoder selection and the status display.

## Design questions

1. What *must* change atomically with the patch index? List the fields.
2. A patch change resets oscillator phases: is the resulting click acceptable, or do you
   crossfade? What would a crossfade cost?
3. What belongs in the table, and what should stay a build-time `#define`?
4. How often must the display refresh to feel live, and how long does one refresh actually
   take? Measure it.

## Compare (spoiler)

- `synth/voices.h`: `Patch`, `kPatches`, `NUM_PATCHES`, and the `constexpr` validators
  `allPatchVoiceCountsInRange()` and `allPatchSpreadsInRange()` in `static_assert`s.
  `patchSpreadsMixed()` drives the display's "*" marker.
- `synth/audio_task.cpp` `applyPatch()`: it re-points the oscillators and renormalizes levels,
  called when `patchIndex` changes, *before* computing the block's volumes. The comment there
  accepts the phase-reset click.
- `synth/controls.cpp` `controlsUpdate()`: `patchIndex` and `freqHz[]` are published in one
  lock. `updateEncoderRotation()` wraps through `NUM_PATCHES`.
- `synth/display.cpp`: `snapshotStatus()` *skips* a refresh if the lock isn't free within
  5 ms. Also `drawRootRow()`, `drawVoiceRow()`, `drawSettingsRow()`, and
  `DISPLAY_REFRESH_MS` 100 in `pins.h`.
- `synth/oscillator.cpp` `initWavetables()`: builds the union over `kPatches`.
