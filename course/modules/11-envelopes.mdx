## Goal

Give notes a beginning and an end: a gated ADSR envelope with musical curves, retriggering and
staccato, applied with no clicks or zipper noise.

## You'll be able to

- Implement ADSR as a state machine with linear and exponential segments.
- Run the envelope at block rate and interpolate it per sample, and explain why both matter.
- Handle retrigger, release-from-anywhere and short notes correctly.
- Choose envelope times that make a patch read as plucked, struck, blown or bowed.

## Concepts

- **The gate.** A key or switch is held. The *trigger* is the rising edge, and release starts
  on the falling edge.
- **ADSR.** Attack to full, decay to the sustain level, sustain while held, release to zero.
  There's an idle state too.
- **Curves.** Linear attack (a constant rise feels fast) versus exponential decay and release
  (loudness is logarithmic). The one-pole "chase the target" form, and time constants (63%,
  or 4.6τ to −40 dB).
- **Control rate vs audio rate.** Compute the target once per block, then ramp per sample.
  A step change of gain every 5.8 ms is a 172 Hz buzz: zipper noise.
- **Retrigger.** Restart attack *from the current gain*, not from 0. Starting from 0 dips the
  level, and the dip is audible as a click.
- **Articulation extras.** Short notes (staccato) get a different release, and auto-release
  after a fixed hold covers sounds that can't sustain forever.
- **Fixed-point ramping.** A per-sample step smaller than 1 LSB truncates to 0. Carry extra
  fractional bits.

## Build

Start from module 10 (patches and a gate switch that currently hard-mutes).

**Add:**

- **An envelope per patch** (all its voices trigger together), configured from the patch
  table. *Example* configs, all times in ms:

  ```cpp
  struct Env { uint16_t attack, decay; uint8_t sustainPct; uint16_t release; };
  constexpr Env kOrgan = {5, 0, 100, 200};    // click-free on/off
  constexpr Env kPluck = {3, 700, 0, 150};    // no sustain, long decay
  constexpr Env kBowed = {10, 100, 90, 200};  // slow-ish attack, high sustain
  ```
- **Gate → noteOn/noteOff**, with the gate from module 05 and the "new root" event from
  module 09 both triggering. *Example* debug trace: `env: ATTACK -> DECAY (412 ms) -> IDLE`.
- **Per-sample ramping** between block targets. *Example:* from gain 0.80 to 0.79 over 256
  samples, the step per sample is 0.00004, well under 1 LSB of Q15. Keep the extra bits.
- **Short notes and auto-release.** *Example:* `shortNoteMs = 250` gives a gate shorter than
  250 ms a 50 ms release; `holdMs = 7000` releases a held note after 7 s.
- **Muting via the envelope**: the gate no longer hard-mutes, and release reaches silence.

**Constraints:**

- The envelope state machine runs once per block. Floats are allowed there.
- The per-sample work is one add and one shift (or similar) per frame. Integer only.
- Retrigger never jumps the gain downward.
- Switching patches mid-note doesn't force a retrigger.

**Deliverable:** an envelope unit, per-patch configs and the per-sample gain ramp in the
audio task.

## Design questions

1. One envelope per patch or one per voice? What do you lose by sharing, and what do you gain
   in cycles?
2. Where does the envelope's gain multiply: per voice, or once on the mix?
3. A gate edge and a new-root event can both arrive within one block. In what order do you
   apply them?
4. How do you define "attack time" for an exponential curve that never quite arrives? When
   do you snap to the target?
