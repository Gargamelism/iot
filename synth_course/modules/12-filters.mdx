## Goal

Add a low-pass filter whose cutoff moves with time and loudness, so sounds change brightness
the way acoustic instruments do.

## You'll be able to

- Read and write a difference equation, and derive a one-pole low-pass's coefficient from a
  cutoff frequency.
- Plot and interpret magnitude response (dB per octave, −3 dB point).
- Implement a recursive filter in fixed point without precision traps.
- Drive the cutoff from an envelope and from a performance control.

## Concepts

- **Difference equations.** FIR versus IIR. The one-pole low-pass `y[n] = y[n−1] + k·(x[n] −
  y[n−1])` (the same form as module 05's EMA).
- **Coefficient from cutoff.** `k = 1 − e^(−2π·fc/fs)`. At `fc ≥ fs/2`, set `k = 1` for an
  exact bypass.
- **Frequency response.** The −3 dB point and a 6 dB/octave slope. Why one pole is "gentle"
  and synth filters are often 4-pole and resonant.
- **Fixed-point IIR.** The state needs extra fractional bits. Without them, small steps
  truncate to zero and the output gets stuck short of its target.
- **Brightness as articulation.**
  - A pluck's high harmonics die faster than its low ones, which you can model as a falling
    cutoff.
  - Brass gets brighter when played louder, which you can model as cutoff scaled by
    loudness.
- **A filter envelope.** A second envelope, triggered with the amp envelope, mapped to a
  cutoff range.

## Build

Start from module 11.

**Add:**

- **A low-pass on the signal path** (on the mix, or per voice: your call). The coefficient is
  updated at block rate and the filter runs per sample in integer math. *Example API*
  (illustrative):

  ```cpp
  int32_t coeffQ16(float cutoffHz);           // block rate
  struct OnePole { int32_t k, y; int16_t process(int16_t x); };  // per sample
  ```
- **Per-patch tone settings:** cutoff min and max, plus a filter envelope. *Examples:*
  - pluck: `{env {1, 300, 20, 150}, 600 Hz .. 10 kHz}`, bright snap, dull within ~0.3 s
  - brass: `{env {80, 0, 100, 100}, 1.5 kHz .. 8 kHz}`, opens as it speaks
  - open: `min = max = fs/2`, bypassed
- **Volume → brightness.** *Example mapping:* `cutoff = min + (max − min) · envGain · (0.3 +
  0.7 · volume)`.
- **A debug print** at block rate, throttled. *Example:* `tone: env 0.42 vol 0.80 -> 3610 Hz
  (k 0.401)`.

**Constraints:**

- No floats per sample.
- The bypass must be *exact* (bit-identical), so "open" patches cost nothing in quality.
- No precision trap at low cutoffs (milestone m12-lowcut).

**Deliverable:** a filter unit, per-patch tone configs, and the filter envelope wired to note
events.

## Design questions

1. Filter per voice or on the mix? With one envelope per patch, does per-voice filtering buy
   you anything?
2. Before or after the amplitude envelope, and before or after distortion (module 14)? Does
   the order change the sound?
3. How many extra state bits do you need at your lowest cutoff? Derive it rather than guess.
4. Is a one-pole enough? What would a resonant 2-pole (state-variable) filter cost per sample?
